Asistente comercial ROMEZ · decisión de base de datos

¿Dónde guarda el asistente el estado de cada chat? Cinco opciones.

Tu n8n del servidor 72.60.15.125 usa SQLite y no tiene Postgres propio. El asistente necesita una tabla chica (romez_chats, una fila por chat). Acá ves cómo son los Postgres que ya tenés, cómo quedaría cada alternativa y cuál recomiendo.

02 · Las opciones

Cómo quedaría cada una

Líneas verdes: conexión permitida. Línea roja punteada: acceso desde internet. El recuadro azul punteado es la red de Docker n8n_default, donde ya vive tu n8n.

04 · Mi recomendación

Opción 2: «como los demás», pero en la red de n8n y sin puerto

Mismo molde que tus otras bases (imagen, reinicio, 512 MB, volumen propio, docker run), con dos diferencias: se une a n8n_default y no publica ningún puerto. n8n lo encuentra por nombre y nadie más lo ve. Es lo que haría, paso a paso:

Qué hace cada paso

  1. Crea el volumen romez_asistente_pgdata (los datos viven ahí).
  2. Genera una contraseña aleatoria y la guarda en /root/romez-asistente-pg.env con permiso 600. No se muestra en el chat.
  3. Levanta romez-asistente-pg con límite de 512 MB, reinicio automático y chequeo de salud.
  4. Crea la tabla romez_chats ejecutando romez_chats.sql dentro del contenedor.
  5. Prueba desde el contenedor de n8n que llega a romez-asistente-pg:5432 y que una consulta responde.
  6. Te doy los datos para la credencial Postgres ROMEZ; la contraseña la leés vos con un comando.

Ver los comandos exactos 
# en el servidor (72.60.15.125)
docker volume create romez_asistente_pgdata
PGPASS=$(openssl rand -hex 24)
umask 077 && printf 'POSTGRES_PASSWORD=%s\n' "$PGPASS" > /root/romez-asistente-pg.env

docker run -d --name romez-asistente-pg \
  --restart unless-stopped --memory 512m \
  --network n8n_default \
  -e POSTGRES_DB=romez_asistente -e POSTGRES_USER=romez_asistente \
  -e POSTGRES_PASSWORD="$PGPASS" \
  -v romez_asistente_pgdata:/var/lib/postgresql/data \
  --health-cmd "pg_isready -U romez_asistente -d romez_asistente" --health-interval 10s \
  postgres:16-alpine

docker exec -i romez-asistente-pg psql -U romez_asistente -d romez_asistente < romez_chats.sql
Respaldo: el estado de los chats se reconstruye solo con el uso (son fichas de conversación), así que no es crítico. Si querés, se puede sumar un pg_dump nocturno, pero no lo incluyo por defecto.
05 · Antes de decidir

Qué cambia si elegís otra

Opción 1 · literal

Copiar exactamente a los demás

Anda, pero publica un puerto Postgres a todo internet y n8n tendría que conectarse por la IP del servidor. Sumaría una cuarta base expuesta. No la recomiendo.

Opción 3 · puerto en el gateway

Publicar solo en 172.18.0.1

Es lo que ya hace wppia (172.18.0.1:3720). Seguro, pero si el servidor reinicia y esa IP todavía no existe, el contenedor puede no arrancar a la primera. La opción 2 evita ese problema.

Opción 4 · reutilizar

consultoria-digital-postgres-1

Habría que conectar un contenedor ajeno a la red de n8n y crear ahí una base y un usuario. Un mantenimiento de esa app corta al asistente y viceversa. Además no pude ver su red ni su usuario.

Opción 5 · sin instalar

Volver a Data Table

Cero cambios en el servidor, pero el estado queda dentro de n8n (SQLite) y se pierde la juntada atómica de ráfagas: con mensajes muy seguidos podría contestar dos veces.

Preparado el 1/11/2026 a partir de una lectura de solo lectura del servidor. No se instaló ni cambió nada. Las valoraciones del punto 3 son criterio propio.
